05 - Where AI Does the Work

Three jobs that don't scale by hand.

None of this is a chat widget bolted onto the page. Each piece replaces a manual task that stops working once the pool gets past a few hundred dossiers.

Verification

Pattern review across the pool

Flags claims that don't match a company's typical process, documents reused across different candidate accounts, and clusters of correlated claims worth a manual look.

→ Fraud checks that don't scale one dossier at a time
Sourcing

Matching, not browsing

A recruiter describes the role; matching surfaces finalists whose cleared rounds actually tested the same skills - including candidates whose title doesn't match on paper.

→ Replaces scrolling a dossier list by hand
Interviewing

Skip-ahead briefs

Before a first call, the hiring team gets a summary of exactly what was already tested elsewhere - system design, case, behavioral - and what's still worth probing.

→ Turns "start over" into "pick up where it left off"

Pipeline

·Redact identity
·Parse the process
·Compute tier (deterministic)
·Re-identification audit
·Publish to the circuit

Why five steps

Redaction runs first and always — if it fails, nothing proceeds. The model proposes a tier but a deterministic rule decides it, and that rule can lower the proposal, never raise it. Brand is not an input: a famous company with one screening call is Standard.

The audit checks how many other live records share your combination of tier, function and region. Below eight, detail gets generalized until it clears. Every step fails closed. Expand any "Show output" box in the demo panel to see exactly what each step produced.

Agent layer

Five agents, one per job.

Each one is a narrow, single-purpose call with its own schema and its own failure mode — not one general-purpose prompt. Three run live in this demo (simulated when no API key is set, so the product stays fully clickable); two describe how the production system works but aren't wired into this static build.

Record Matcher

Model

Ranks anonymized records against a role description by competency overlap, not keywords — every result names at least one gap, never just a pitch.

In: role text + candidate pool (already floor-filtered)
Out: fitScore, matched[], gaps[], rationale per record

Interview Brief

Model

Written once an intro is approved: what's already been assessed, what's safe to skip, what to probe instead. This is what makes "start at round four" real.

In: the approved record
Out: alreadyAssessed[], safeToSkip[], probeInstead[], neverSkip[], recommendedQuestions[]
—

Redaction

Deterministic

Regex pass that strips emails, phone numbers, URLs and @handles before any text reaches a model. Runs first, always, on every listing and every reply.

In: raw candidate text
Out: cleaned text + count of what was removed
Always active — no model in the loop

Redaction Audit

Deterministic here

Checks a record against the live pool before publish: does it share tier, function and region with at least 8 others? Below that floor, detail is generalized until it clears — never published thin.

In: the record + a live cohort count
Out: k, decision (publish / generalize), generalization steps
Active — the k-anonymity floor is code, not a model call, in both this demo and production (the model-scored risk pass in src/redactionAudit.ts isn't wired into this static build)

Pattern Review

Model · batch

Phase-2 fraud/inflation detection — reads across the pool for records that don't match a company's typical process, reused evidence, or coordinated gaming. Runs in batch, never on the write path.

In: a record + pool statistics + near-duplicate score
Out: signals[], recommendation (clear/flag/hold)
Not wired into this demo — no write-path or admin queue exists here yet

Why filters run first

Your tier and evidence floors are enforced in code, never passed to the model as an instruction. A model that can be talked out of a floor can be talked out of a blocklist, and that is a privacy incident rather than a ranking bug.

Every row names a gap

A rationale with no negative in it is a sales pitch, and it teaches recruiters to stop reading rationales. If the model returns one without a gap, it's rejected.
